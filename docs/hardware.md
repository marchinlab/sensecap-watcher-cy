# 硬件与固件

## 1. 设备

| 项目 | 参数 |
|---|---|
| 型号 | Seeed Studio SenseCAP Watcher |
| 主控 | ESP32-S3 |
| 存储 | 16 MB Flash / 8 MB PSRAM |
| 屏幕 | 1.5 寸圆形触摸屏，480 × 480 |
| 外设 | 摄像头、麦克风阵列、扬声器、环境光传感器、旋钮 |
| 固件框架 | ESP-IDF v6.0 + LVGL |

选它的原因是：圆形屏 + 摄像头 + 扬声器一体成型，适合做"有表情的桌面终端"；且官方固件开源，允许刷入完全自研的固件。

---

## 2. 固件结构

自研部分集中在三个模块：

| 模块 | 职责 |
|---|---|
| 收件箱轮询 | 定时拉取增量消息、判断设备忙闲、唤醒设备后投递 |
| 表情状态机 | 眼睛与表情的动画、人脸朝向驱动、优先级仲裁 |
| 串口调试 | 运行时命令：查看状态、切换表情、注入朝向、解除注入 |

其余（配网、音频编解码、UI 框架）复用上游工程。

---

## 3. 分区与升级

设备使用**双 OTA 分区**：

```
bootloader | partition table | ota_data | ota_0 (运行) | ota_1 (备用) | 资源分区
```

烧写规则：**运行分区与备用分区必须写入同一份镜像**。只写一个分区时，一旦触发回滚，设备会启动另一个分区里的旧固件，表现为"烧了新版本但版本号还是旧的"——这个现象极具迷惑性，排查过很久。

发版流程固定为六步：

1. 修改版本头（版本号 / 日期 / 变更摘要）
2. 编译
3. **校验镜像内的版本串与版本头一致**（编译发生在改版本号之前，是最常见的"备份了旧镜像"的来源）
4. 备份可回滚的完整镜像集合
5. 台账记录（版本号、变更、已知问题、回滚路径）
6. 双分区烧写并读串口验证

## 4. 串口调试

设备保留运行时命令通道，用于在真实设备上做对照实验：

| 命令 | 作用 |
|---|---|
| `version` | 查固件版本 |
| `eyes mood <name>` | 切换表情（会锁定，测完需恢复自动） |
| `eyes on` / `eyes off` | 显示/隐藏眼睛，用于分离"渲染故障"与"逻辑未执行" |
| `eyes gaze` | 注入朝向，带超时自动回落 |
| `eyes gaze off` | 立即解除注入 |

**方法论**：当"播报时眼睛不跟随"这类问题时，正确的做法不是改代码猜，而是在播报进行中用串口逐项干预 —— 手动切表情能看到变化，说明渲染没问题；看不到变化，说明是显示被冻结；切了没反应但确实在渲染，说明状态机没跑。三种可能一次性区分开。

## 5. 已知坑位

| 现象 | 根因 | 结论 |
|---|---|---|
| 开机后 2.5 秒一次无限重启 | 开机早期网络栈未就绪即发起请求，触发协议栈断言 | 网络相关状态判断**必须用白名单**，不能用黑名单排除 |
| 待机来消息不开口 | 轮询只在空闲态进行，设备停在聆听或省电降频后永不拉取 | 轮询白名单要含聆听态，投递前先退出省电档 |
| 待机播报"像没反应" | 待机时背光被压到极低、CPU 降频 | 投递链路第一步就是唤醒，且必须投递到主任务 |
| 眼睛永久锁死朝向 | 调试注入置位后不再读摄像头，且无超时 | 注入必须带超时 + 显式解除 |
| 烧了新固件但版本号没变 | 只写了一个 OTA 分区，回滚到旧分区 | 双分区写同一镜像 |
| 读串口时设备反复重启 | 打开串口时拉低 DTR/RTS 触发了复位 | 只读时不要动 DTR/RTS |
